A coding agent that has to prove its fix.

issue-agent reads a bug report, edits the code, and runs the tests. Then tests it never saw decide whether the fix was real.

    How it works

    The agent is a loop around a language model. Each step is something the model asks for and the code carries out.

    1. Read the report

      The issue text and the repository go to the model.

    2. Look around

      It lists files, searches, and reads code. It cannot run shell commands.

    3. Edit

      It replaces exact text in a file. An edit that matches more than once is rejected.

    4. Run the tests

      Tests run in a Docker container with no network. The agent reads the result and tries again if needed.

    5. Hidden tests judge

      When the agent stops, tests it never saw are added. Passing only the visible ones is labelled overfit.

    Does the careful prompt help?

    I compared the two prompts on 10 held-out bugs, repeating each one 2 or 3 times. A run counts as solved only if the hidden tests pass.

    What this does not show

    • The bugs are small and hand-made. This is a pilot study, not SWE-bench.
    • Tasks 23 to 27 were written after v1 failed on task 22, so they may lean toward what v3 targets.
    • Hidden tests check edge cases, which suits a prompt that asks for edge-case thinking. Real issues do not come with hidden tests.
    • Two or three runs per setting show a consistent difference, not a statistical proof. Only one model was tested.
    • A third prompt (v2) also scored 100%, but its examples overlapped the hidden tests, so I discarded that result.

    Tests run in a throwaway container

    Model-written code should not run on the machine that holds your secrets. With the sandbox on, every test run happens in a fresh Docker container.

    The container covers test execution. The agent's edits happen in a temporary copy of the repository, and Docker is not a perfect security boundary.
